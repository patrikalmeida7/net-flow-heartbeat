- Multi-tenant: tenant data carries `organization_id` (table `organizations` + `organization_members`, check via `is_org_member`); keeps the SaaS path open without rewriting tables later.
- MikroTik API devices live in `mikrotik_api_credentials` (password encrypted, readable only by service role); collectors pull them from the `mikrotik-agent-config` function, so adding a device never requires editing config.json on the VPS.
- Primary monitoring uses source-specific SNMP state/timestamps through metrics-ingest; agent-ingest emits connect/disconnect/mass events only for `source=routeros_realtime` (persistent API session polled ~60s); legacy snapshots never emit events and an empty list after many online is ignored, so collectors cannot manufacture outages. API never changes SNMP device status. API interfaces stay in a separate JSON photo; SNMP counters alone own interface deltas.
- SNMP persistence uses a service-role-only per-device transaction and timestamp/payload receipt; counter-width changes reset delta baselines, and persistence errors never advance SNMP observation timestamps.
- RouterOS API uses one persistent session per device (login once, reconnect only after error) to avoid login/logout log spam; API interfaces are pushed at most every 6h.
- Agent image builds must run `npm run check:syntax` over every JavaScript file in `agent/src` before dependency installation; syntax errors must prevent publishing a broken image.
- SNMP credential secrets are not client-readable; admin saves through save_snmp_credentials and assigns an agent matching the target organization, so SNMP-only devices retain tenant isolation.
- A PPPoE client is identified by `concentrador_id + username` (routes `/pppoe/c/:concentradorId/:username`); lists/totals come from server RPCs (`pppoe_clients_page`, `eventos_page`, `*_summary`) to avoid the 1000-row cap.
- Mass drops are one `device_down` event with `metadata.scope='mass'` + `count`/`usernames`; individual drops are `disconnect`. Reports/alerts must count both but never treat mass drops as client instability.
- WhatsApp sends go through `deliver()` with per-recipient rows in `notification_deliveries` (retry only pending, max 3) and a `job_locks` lock; pure logic lives in `notify-whatsapp/logic.ts` and is unit-tested from `src/test`.
- Access is granted only by `access_authorizations` (admin-managed, exact normalized e-mail, active/blocked); `has_role`/`is_authorized` read it live, so blocks hit open sessions and every RLS/RPC/function. `user_roles` is deprecated; never grant roles on signup.
- Custom dashboards store panel layout in `custom_dashboards` (admin writes, authorized reads); charts read server-bucketed `metric_series` (avg+max per bucket) and `metric_catalog` so panels never pull raw history or trigger collection.
- TR-069 uses GenieACS (one instance per organization, installed closed, CPE auth tested before opening); NOC-ISP talks to its NBI only over HTTPS via `tr069-bridge` (logic in dependency-injected `handler.ts` + pure `logic.ts`, tested from `src/test`), which re-checks org/server per action, keeps ACS passwords AES-GCM encrypted in service-role-only `acs_server_secrets` with a backend secret key, persists tasks with a client request_id and frozen profile snapshot before sending, treats timeouts as unknown, and confirms only by reads newer than the request (passwords never confirmed); reconciliation never resends commands and bounds CPE reads via a compare-and-set counter on the task; the installer keeps secrets out of process argv.
- RLS policies wrap auth helpers as `(SELECT fn((SELECT auth.uid())))` so they run once per query, not per row (per-row calls made interface lists ~0.8s).
